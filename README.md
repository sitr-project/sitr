# سِتر | SITR

مشروع ستر يتضمن موقعًا عربيًا تعريفيًا وإضافة تجريبية لمتصفحات Chrome وEdge على الكمبيوتر. الإضافة تحجب نطاقات الويب التي يختارها المستخدم بالكامل، وتحفظ إعداداتها محليًا. لا يوجد تطبيق Android أو حجب انتقائي للصور والمنشورات.

## ما يعمل الآن

- صفحة تعريفية عربية باتجاه RTL، متجاوبة مع الشاشات الصغيرة والكبيرة.
- إضافة Chromium تجريبية تحجب نطاقات مواقع كاملة عبر `declarativeNetRequest`، مع تشغيل وإيقاف واختيار نطاقات مخصصة.
- إعدادات الإضافة محفوظة في `chrome.storage.local` ولا ترسل بيانات إلى خادم.
- اختيارات المحتوى والمنصات ومستوى التصفية في صفحة الموقع التعريفية تُحفظ في `localStorage`، لكنها لا تتحكم بإضافة المتصفح.
- نموذج الملاحظة يحفظ النص محليًا فقط؛ لا يُرسل أي طلب شبكة ولا توجد لوحة إدارة للملاحظات.

الإضافة تحجب الموقع المختار بكامله، ولا تصنّف محتوى الصور أو الفيديو أو المنشورات. لا تعمل داخل تطبيقات Android/iPhone، ولا تعمل على Chrome للجوال. إزالة الإضافة تحذف إعداداتها.

## تثبيت إضافة المتصفح

راجع [دليل الإضافة](./browser-extension/README.md). باختصار: نزّل ZIP الإضافة من زر التنزيل في الموقع، فك الضغط، افتح `chrome://extensions` أو `edge://extensions`، فعّل وضع المطور، اختر **Load unpacked** ثم المجلد الذي يحتوي `manifest.json` مباشرة. اختر نطاقًا واضغط حفظ ثم تشغيل الحماية.

لا تنشر الإضافة في Chrome Web Store أو Edge Add-ons بعد. التثبيت الحالي يدوي وتجريبي.

## التشغيل على Windows 10

لا تحتاج إلى تثبيت حزم أو إنشاء بيئة افتراضية لتشغيل الموقع.

1. ثبّت Python 3 من [python.org](https://www.python.org/downloads/windows/) إن لم يكن مثبتًا، وفعّل خيار إضافته إلى PATH.
2. افتح PowerShell وانتقل إلى المجلد الذي يحتوي على `index.html`:

   ```powershell
   cd "C:\Users\Fr\Desktop\مشروع ستر"
   ```

3. شغّل خادم الملفات المحلي المرفق مع Python:

   ```powershell
   py -m http.server 8000
   ```

4. افتح `http://localhost:8000` في المتصفح. لإيقاف الخادم اضغط `Ctrl+C`.

يمكن نشر الملفات الثابتة كما هي على GitHub Pages أو Cloudflare Pages أو أي استضافة ملفات ثابتة. يوفّر الموقع ZIP المستودع لتنزيل الإضافة؛ بعد أي تعديل يجب رفع التغييرات إلى GitHub وإعادة نشر الموقع حتى يحصل الزوار على النسخة الجديدة.

## اختبار الموقع

1. افتح الصفحة وتحقق من الروابط في القائمة، ثم جرّب عرضًا ضيقًا أو محاكي الهاتف في أدوات المطور.
2. في «إعداداتي»، اختر فئات ومنصات ومستوى، واحفظ. أعد تحميل الصفحة وتحقق من بقاء الاختيارات.
3. تذكر أن إعدادات الصفحة التعريفية منفصلة عن إضافة المتصفح.
4. أرسل ملاحظة تجريبية. يعرض النموذج أنها حُفظت محليًا فقط؛ لا توجد خدمة إرسال.
5. في نافذة متصفح خاصة أو بعد مسح بيانات الموقع، تحقق من أن الاختيارات السابقة غير موجودة.
6. ثبّت إضافة المتصفح واختبر حجب النطاق وإيقافه وفق الخطوات في `browser-extension/README.md`.
7. اختبر لوحة المفاتيح: `Tab` للتنقل، و`Enter` لفتح الروابط، ومفاتيح الأسهم أو المسافة لعناصر النماذج. يمكن أيضًا التحقق من أن القائمة المنسدلة تعمل على الهاتف.

لا تدّعي هذه الخطوات نجاح تصنيف الصور والفيديو؛ الإضافة تختبر حجب نطاقات المواقع فقط.

## حدود الحجب وخطة Android

إضافة المتصفح هنا يمكنها حجب نطاقات مواقع الويب كاملة، لا محتواها انتقائيًا. موقع ويب عادي لا يمكنه مراقبة تطبيقات أخرى. تطبيقات Android لا تكشف تدفق المحتوى الداخلي تلقائيًا لتطبيق ثالث. كما أن تحليل الشاشة بتقنيات إمكانية الوصول حساس للخصوصية، محدود وغير مضمون، ويخضع لقيود Google Play وسياساتها.

المراحل المقترحة قبل إطلاق تطبيق:

1. بناء تطبيق Android أصلي بـ Kotlin وواجهات Android الحديثة، لحفظ التفضيلات محليًا، وشرح الصلاحيات والموافقة عليها.
2. اختبار الخيارات المسموح بها على أجهزة فعلية. يمكن دراسة فلترة نطاقات الويب عبر `VpnService` محلي، لكنها لا تفحص فيديوهات أو منشورات داخل التطبيقات المشفرة ولا تساوي حجب محتوى الصور. أما `AccessibilityService` فليس اختصارًا مضمونًا لتحليل الفيديو؛ لا يُستخدم إلا لحاجة أساسية واضحة، بموافقة المستخدم، وبما يتوافق مع سياسة إمكانية الوصول ومتطلبات الإفصاح في Play.
3. إذا ثبتت جدوى تحليل الصور على الجهاز، يمكن إضافة نموذج صغير يعمل محليًا (مثل TensorFlow Lite) وتقييم الدقة والموارد والخصوصية قبل ربطه بأي إجراء حجب. يجب توفير تشغيل/إيقاف واضح، ومراجعة للأخطاء، وخيار تعطيل أي صلاحية.
4. لا يتطلب تطبيق الإعدادات المحلي خادم Python. يمكن إضافة FastAPI لاحقًا لخدمات اختيارية مثل استقبال بلاغات بموافقة صريحة، لكن لا ينبغي رفع صور أو فيديوهات للتصنيف افتراضيًا. لا يوجد خادم أو اتصال API في هذا الإصدار.

حتى بعد تنفيذ المراحل، لا يمكن ضمان قراءة أو تصفية كل محتوى TikTok أو YouTube أو Instagram أو X داخل تطبيقاتها الرسمية. يجب اختبار كل ميزة، والإفصاح عن محدوديتها، ومراجعة سياسات Android وGoogle Play قبل النشر.

## تجهيز APK والنشر على Google Play (للمرحلة المستقبلية)

لا يوجد APK في هذا المشروع حاليًا. عند اكتمال تطبيق Android:

1. ثبّت Android Studio وAndroid SDK، وأنشئ مشروع Android أصليًا مستقلًا (مثلًا ضمن `android/`).
2. اختبر على محاكي وجهاز فعلي، وراجع طلبات الصلاحيات واستهلاك البطارية وسلوك إيقاف الحماية.
3. من Android Studio اختر **Build > Generate Signed Bundle / APK**؛ أنشئ مفتاح توقيع آمنًا واحتفظ بنسخة احتياطية منه. لا تضع المفتاح أو كلمات مروره في المستودع.
4. للاختبار المباشر يمكن إنشاء APK موقّع. للنشر على Google Play، جهّز غالبًا Android App Bundle (`.aab`)، مع صفحة سياسة خصوصية وإفصاحات دقيقة عن البيانات والصلاحيات، وتصنيف المحتوى، ولقطات الشاشة، وإكمال نماذج Play Console.
5. ابدأ باختبار داخلي/مغلق، ثم اطلب المراجعة والنشر. متطلبات Google Play وسياساته تتغير؛ راجعها وقت التقديم، خصوصًا قواعد Accessibility API وVPNService والبيانات.
6. بعد نشر التطبيق أضف رابط صفحة المتجر أو ملف التنزيل الرسمي في الموقع.

تتطلب حسابات النشر وبعض خدمات Google Play رسومًا أو مراجعات وفق شروط Google السارية؛ أما الاستخدام الأساسي للموقع فمجاني.

## iPhone

قد تسمح Apple بميزات محدودة من خلال Screen Time وFamily Controls مع الاستحقاقات والموافقات اللازمة. لا تمنح هذه الواجهات تطبيقًا حرية فحص أو التحكم في المحتوى داخل أي تطبيق آخر. يتطلب دعم iOS تطبيقًا أصليًا واختبارات ومراجعة منفصلين؛ لا يوجد دعم iPhone في النسخة الحالية.
